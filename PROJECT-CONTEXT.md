## Decisions (with reason)
- 2026-11-04 — Direction: dark green premium tech. Dark shell, light content sections.
- 2026-11-04 — Font: Readex Pro for both Arabic and Latin.
- 2026-11-04 — Calligraphy background: `public/images/patterns/calligraphy-on-dark.v1.svg` at 8% opacity, dark sections only (hero, dark bands, footer), never behind products/prices/body text; merchant can toggle it. Glyphs from Aref Ruqaa (OFL 1.1); generator script kept outside the repo.
- 2026-11-04 — Calligraphy settings: `calligraphy_bg_enabled` (switch, default on) and `calligraphy_bg_strength` (subtle 5 / standard 8 / strong 12) in twilight.json; `useCalligraphy()` returns the class and `--calligraphy-opacity`. First applied to `.site-header__topnav`, only when `topnav_is_dark` is on (slider images would cover the pattern; the footer is an engine component). Plain Arabic labels because the local editor showed `{ar,en}` objects as the raw id.
- 2026-11-04 — Phase 2 decisions: the mobile bottom bar goes dark (`bg-darker`); active tab = white pill with a green `--lameem-primary` icon (not `--color-primary`). Logo: new `logo_on_dark` image setting, falling back to the store logo; no white-filter option. New `header_is_dark` setting (default on) for the main bar; `topnav_is_dark` controls the top bar only. New setting labels are plain Arabic strings in twilight.json; locale files only for shopper-facing text. Build order: footer → header → bottom bar (all done).
- 2026-11-06 — Phase 3 plan approved. Build order = hero → features → how-it-works → reviews → FAQ → animated product showcase (new block, last). Showcase: desktop hover = wallet cards slide straight out of the RIGHT side in a staircase (back card furthest); the key organizer swings its keys out around the pivot; on phones it plays once on scroll-in; click → product page; reduced-motion = still image; layered images + CSS, no new dependency; needs layered renders/photos from the client. Prototype: https://claude.ai/artifact/NJATEfbpUMkXfPq8Dcna6q
- 2026-11-06 — Phase 3 rules: `sicon-*` icons are OK for features/steps for now. Calligraphy may sit behind hero/step text with a fade behind the text column. Never invent product claims or reviews in the theme; sample content lives only in `twilight.preview.json` (gitignored) and is marked "نص تجريبي". New home blocks: `home.hero` (step 1), `home.how-it-works`, `home.faq`, showcase; features strip = restyle of engine `store-features`; spotlight = restyle of `fixed-products`; reviews = extend `custom-testimonials` (declare `title`/`description`, relax `avatar`).
- 2026-11-06 — Surface roles (fixes the "one solid green block" look): each dark surface has its own role and the calligraphy appears once per screen. Header (top bar + main bar) = solid `bg-darker` (--lameem-deep) with a thin `border-white/10`, no calligraphy; mobile bottom bar = solid `bg-darker`, no calligraphy (the hero carries the pattern on phones); the hero has depth — radial glow (`--lameem-glow` #1d4a35 → primary → deep) behind the product side, five thin radar rings plus one slow pulse ring (off for reduced motion), calligraphy fading out behind the text column and toward the edges; footer keeps the pattern at 60% of the chosen strength (`useCalligraphy(0.6)`). The `calligraphy_*` and `header_is_dark`/`topnav_is_dark` settings are kept; they no longer drive the header or bottom bar pattern.
- 2026-11-06 — Pattern v2: the generator (`C:\salla-theme-kit\tools\calligraphy\gen.js`, v1 kept as `gen.v1.js`; the number-joining bug that merged coordinates, e.g. "-14" + ".5" → "-14.5", is fixed in v2) mixes in simple location symbols (map pin, radar arcs, crosshair, signal waves; 38 of 256 cells), output `calligraphy-on-{dark,light}.v2.svg` (55.6 KB each) copied to `public/images/patterns/`; `calligraphy.scss` points at v2; the v1 files stay for now.
- 2026-11-06 — Animated products live in the hero first (the standalone showcase block comes later and reuses `ProductShowcase.tsx`). Hero fields: `animate_products` switch + per product (`p1_*`, `p2_*`): `_link`, `_name` (screen-reader label), `_type` (slide / swing), `_body`, `_layers` (collection, max 3), `_pivot_x/_y` (swing). Switch off or a product missing its link / body / layers → that product is left out; none left → the single hero `image`. Layers of one product share one canvas, fixed per type (slide 520×900, swing 600×900) so the box is reserved before load; layers listed nearest-first (slide: the last card travels furthest, 16/31/45% of the canvas width, 80ms stagger; swing: inner blade first, outer last, closed -30°/-55° → open 0°/6°). Art never mirrors in RTL (row is `dir=ltr`; cards slide physical right). Desktop opens on hover/focus, touch opens once 600ms after in view, reduced motion = open and still. Layer weight with the first set of art: ~99 KB (bodies 53 KB eager, 5 layers 46 KB lazy).
- 2026-11-06 — Showcase tuning, approved in the browser. Gap between products is 0.07 of the canvas height: the open cards reach ~0.15 past the wallet canvas and the key body starts ~0.14 into its own canvas, so 0.07 leaves ~20px clearance at 1280 while the closed products sit close. From 1536px the showcase grows (`--showcase-height` 28rem → 32rem, hero media max 42rem) and the hero grid becomes 1fr / 1.25fr so the column does not cap it. A link field may arrive as a string, [{value}] or {value}; `linkUrl()` reads all three.
- 2026-11-06 — Dev preview images must be named `<16 hex of sha256>.<ext>` in `twilight-preview-assets/` (the dev server only serves that pattern); uploading through the editor does this itself.
- 2026-11-06 — Features strip = a theme-owned block `home.features` (key 0bb87fde-…), not a restyle of engine `store-features`: that block is platform-fed (the theme declares no fields, the docs give no item limits or preview shape), so a merchant could not be guaranteed 2–6 items with icon + title + text. `items` collection 2–6, fields `icon` (format `icon`), `title`, `text`; column count follows the item count (2 on phones, up to 4 from 1024px, 5–6 wrap). Light `--lameem-light` surface, white tiles, 56px `--lameem-primary` icon circle with two faint CSS rings, gray-600 text, no calligraphy. Styles in `home-features.scss`. The engine `store-features` paragraph also went from gray-500 to gray-600 (contrast). Icons are validated against `^sicon-[a-z0-9-]+$` before reaching `className`.
- 2026-11-06 — Product facts (client): both products come in the same 5 colours (black, grey, blue, olive, orange). The key organizer has a power button and a "Locate with Apple Find My" badge; the wallet photos show none. OPEN client questions (copy is blocked on them, not the build): Find My certification (badge/wording only if certified), which products track, wallet card direction (photos suggest out of the top), Android users. So the theme makes NO real tracking claims; the how-it-works block carries sample text only (twilight.preview.json).
- 2026-11-06 — `home.how-it-works` (key d8d09b8a-…): theme-owned block, fields `title`, `subtitle`, `steps` (2–4: `icon`, `title`, `text`), optional `image`. Own dark surface role: `--lameem-deep` + thin white/10 lines top and bottom + calligraphy at `useCalligraphy(0.6)` masked thinner behind the centre. Phones: vertical list, number on the inline-start side, dashed vertical connector; from 1024px a row with a dashed sideways connector; WITH an image the steps stay vertical beside it (a row would be too narrow). Numbers via `Intl` (ar-u-nu-arab / en-u-nu-latn). Reveal: IntersectionObserver staggers steps 120ms; reduced motion or no IO = shown at once (never hidden before JS). Text: white titles, `--lameem-muted` text on the deep surface. Fewer than 2 titled steps renders nothing.
- 2026-11-06 — Wide-screen fix: the features grid had `margin: 0` on its `container` element, which cancelled the container's auto inline margins, so above 1280px it hugged one edge (x=625 at 1920 in RTL) instead of lining up with the hero and how-it-works content (x=313). Now `margin-block: 0`. Rule for new blocks: never reset `margin` (shorthand) on an element that also carries `container`; verify at 1920px as well as 375/1280 (all three blocks now align at 1920, ar and en).
